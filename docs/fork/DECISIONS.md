# Журнал решений форка

Каждое решение владельца по форку — одной датированной записью, новые сверху. Запись не
переписывается задним числом: если решение меняется, пишется новая запись со ссылкой
«отменяет …». Текущий план и состояние — в [README.md](README.md).

---

## 2026-10-12 — форк становится своей дистрибуцией: «OS для программиста»

Отменяет: «вся работа только PR-ами в апстрим» (`FORK.md` до 12.10) и пункт «что уходит в
апстрим — всё, кроме личных значений» от 2026-09-27.

1. **Модель форка — принята.** `main` форка — рабочая сборка OS: апстрим + свои модули и
   фиксы; отсюда OS ставится в проекты. Причина владельца: «хочу больше уйти в прогерскую OS,
   а изначальная она для всего». Как именно работать с ветками — [FORK.md](../../FORK.md).
2. **Что уходит в апстрим.** Общие вещи, полезные любому пользователю SREDNOFF OS: баги самой
   OS (первый кандидат — перезатирание CLAUDE.md и файлов проекта), исправления без
   зависимостей от форк-кода. Всё «для программистов» — модули E1/F1, плейбук D1–D10
   (карточки, страж области, ADR, BDD/тест-first практики и т.п.), X*, O*, C* — остаётся в
   форке. Метки в задачах: `upstream-candidate` / `fork-only`.
3. **Версия форка** — отдельным файлом [`FORK-VERSION`](../../FORK-VERSION) в формате
   `v<версия апстрима>+elysosss.<N>`; `registry/version.json` апстрима не трогаем, чтобы синк
   не конфликтовал. `N` растёт на каждом значимом мерже в `main` форка.
4. **Фикс перезатирания — семантика «create-only».** Повторные и фоновые запуски установки
   только создают недостающие файлы и никогда не меняют существующие (отличия печатаются
   списком); заменить файл можно только руками и явным флагом. CLAUDE.md проекта без явного
   флага не меняется никогда, включая блок SELECTION от `gen-profile-lock`.
5. **Все решения, планы и состояние работ живут в репозитории** (`docs/fork/`), чтобы
   продолжать с любого ПК. Файл `HANDOFF.md` в рабочем каталоге — только указатель сюда и
   машинно-локальные заметки.

Уточнить при случае: «BDD» в п. 2 — это практики для проектов, которые ведёт OS (сценарии
как спецификация фич, тест до кода — D7, D2 `kind: test`), а не тест-контур самой OS: там
действует решение 2026-09-27 «run-evals, без behave». Если имелся в виду отдельный модуль
«BDD для проектов» — завести спеку.

## 2026-09-27 — решения по спекам расширений

Полная таблица — [docs/specs/README.md](../specs/README.md#решения-владельца-2026-09-27).
Кратко: F1 собирается локально на Go 1.27; таблица «метка → секрет» в памяти + зашифрованная
копия на диске (DPAPI); плейсхолдер в shell → `ask`; движок — свой демон на `pkg/`
guardrails; Firebird — только пароли, Bybit — HMAC и RSA; хуки модулей — в
`settings.local.json`; установка модулей только в папку проекта; тесты — `run-evals` без
behave; ядра D6/D7/D10 — парные `.ps1`/`.sh`; карточки D2 — подмножество YAML; агент на
GitHub под учёткой владельца (соло-режим D8); живые пробы O3 — только по команде; второго
аккаунта (O4) нет; сжатие контекста (C2) — сначала замер M1.

## 2026-09-13 — OS ставится только в папку проекта

Глобальная установка (`install-claude-md-os`, запись в `~/.claude/{CLAUDE.md,
code_review.md,templates,registry}`) запрещена; владелец жёстко подтвердил после того, как
глобальный установщик был запущен и откатывался руками. Проверки, которым нужна раскладка
`~/.claude`, гоняются во временном HOME.

В тот же день: снято переуказание marketplace-команды на форк — апстрим взял все фиксы,
обоснование «форк полнее» перестало быть правдой.

«всё апстримом» — отменено 12.10.

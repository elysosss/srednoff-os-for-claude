# O6: Бэкап и экспорт конфигурации OS

> Статус: DRAFT
> Тип: спека-набросок
> Модуль E1: не модуль — скрипты ядра `scripts/os-export.{ps1,sh}`, `scripts/os-import.{ps1,sh}`
> Зависит от: E1 (`installed.json`, метаданные модулей), O4 (профили)   Блокирует: —

## Goal
Снять переносимый слепок **конфигурации** OS проекта (что установлено, как настроено, какие профили) и восстановить его в другом проекте или на другой машине — так, что в слепок по построению не может попасть секрет.

## User value
Сейчас настройку OS в проекте (какие хуки включены, модули, профили, PROFILE.lock) повторяют руками. Закрыто, когда `os-export` → `os-import` в пустой проект даёт тот же вердикт `/os-doctor`, а слепок проходит секрет-скан.

## Non-goals
- Не бэкап данных: транскриптов, авто-памяти, логов, состояния демонов.
- Не бэкап форка OS — для этого git.
- Не шифрование архива: вместо «зашифровать секреты» — «не брать секреты» (OmniRoute шифрует бэкап, потому что кладёт туда БД с учётками; нам это не нужно).
- Не синхронизация между машинами в фоне.

## Current state
`init-claude-project` умеет развернуть OS, но не знает о модулях и настройках; безопасная семантика перезаписи у него уже есть (отслеживаемые git-ом отличающиеся файлы не трогает, неотслеживаемые — `.bak`). Хуки пишут журнал в `~/.claude/logs/hook-events.jsonl` (sha256 входа, не секрет), маркеры — в `~/.claude/logs/session-state/`.

## Assumptions
- `ASSUMPTION:` значения `userConfig` с `sensitive: true` (PF-17) хранятся только в хранилище ОС и не дублируются в файлы плагина/проекта. Проверить: установить тестовый плагин с sensitive-полем, `grep` значения по `~/.claude` и проекту.

## Architecture (дизайн)
**Allow-list по путям и по ключам.** Экспортируется только перечисленное; всё остальное — в список `excluded` манифеста (путь и причина, без содержимого).
| Входит | Как |
|---|---|
| `installed.json` | целиком, без абсолютного `osRoot` (заменяется на `<osRoot>`) |
| `config/*.json` модулей (пользовательские переопределения) | ключи из `metadata.srednoffOs.config.sensitiveKeys` модуля вырезаются |
| `.claude/settings.json` | **только** ключи `hooks`, `permissions`, `disableAllHooks`; `env`, `apiKeyHelper`, `mcpServers`, всё прочее — нет |
| `.claude/PROFILE.lock.md`, проектные правила сверх 00–90, проектные команды | файлами |
| профили O4 (`type: overlay`) | без `env`; `isolated` — только имя, без `configDir` |
| контексты O5 | только имена и профиль; хосты/пути — с `--include-hosts` |
| версии: OS, модулей, Claude Code | в манифест |

| Никогда не входит | Почему |
|---|---|
| `.credentials.json`, любой `CLAUDE_CONFIG_DIR`, хранилище ОС | учётные данные |
| состояние F1: таблица соответствий, плейсхолдеры, кеш | содержит оригиналы секретов |
| `.claude/settings.local.json`, `.env*`, `*.pem|*.key` | личное/секреты |
| `~/.claude/projects/**` (транскрипты, авто-память), `~/.claude/logs/**` | данные разговоров и аудит |
| `.claude/os-modules/.state/**` (sysinfo, пробы, runtime-маркеры) | производное, машинное |
| `${CLAUDE_PLUGIN_DATA}` | данные плагинов |

**Гейт fail-closed**: собранный слепок целиком прогоняется через секрет-скан `hook-lib` (контент) и путевые правила `protect-secrets`. Любое совпадение → слепок удаляется, печатаются файл и правило, выход 3. Частичного архива не остаётся.

**Импорт**: по умолчанию `--dry-run` — печатает план (`+` создать, `=` совпадает, `!` отличается и отслеживается git-ом — не трогать, `~` отличается, не отслеживается — `.bak` и заменить); применение — `--apply`. Хуки в `settings.json` сливаются через установщик E1 (по имени модуля), файл не перезаписывается. Модули, которых нет в `<osRoot>` на целевой машине, отмечаются `missing`, не ставятся молча.

## API contracts (интерфейсы и форматы)
`os-export -Out <dir|file.zip> [-ProjectPath .] [-IncludeHosts]`; `os-import -From <path> [-ProjectPath .] [-Apply]`. `-Out` обязателен; путь внутри `~/.claude` отвергается (HANDOFF §2); путь внутри git-рабочей копии принимается, только если он игнорируется. Коды: 0 ок; 3 секрет-скан; 4 недопустимый `-Out`; 5 версия схемы манифеста новее поддерживаемой.
```json
{ "schema": 1, "createdUtc": "...", "osVersion": "1.12.0", "claudeCode": "2.1.177",
  "modules": [ { "id": "f1", "version": "0.1.0", "mode": "enforce" } ],
  "files": [ { "path": ".claude/PROFILE.lock.md", "sha256": "..." } ],
  "excluded": [ { "path": ".claude/settings.local.json", "reason": "personal" } ] }
```

## Data model / migrations
Слепок = каталог или zip с `manifest.json`. `schema` растёт только добавлением полей; импорт старой схемы поддерживается всегда, новее — отказ с кодом 5.

## Security model
Угрозы: секрет в слепке (через `env`, конфиг модуля, профиль), персональные данные (хосты, пути с именем пользователя), подмена слепка перед импортом. Защита: allow-list путей и ключей, `sensitiveKeys` модулей, fail-closed скан, обезличивание путей (`~`, `<osRoot>`), sha256 в манифесте проверяется при импорте. Не защищаем от: злонамеренного слепка с вредным хуком — импорт показывает хуки в плане и требует `--apply`; доверие к источнику — решение владельца.

## Risks
| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Модуль не объявил sensitive-ключ | средняя | высокое | fail-closed скан; контракт E1 требует `sensitiveKeys` (пустой массив — явно) |
| Импорт затирает ручные правки | низкая | среднее | семантика `init-claude-project` + `--dry-run` по умолчанию |
| Слепок устаревает относительно модулей | средняя | низкое | версии в манифесте, `missing` при импорте |

## Acceptance criteria
- AC1 `env.ANTHROPIC_API_KEY` в `settings.json` не попадает в слепок, а `hooks` попадают (S1).
- AC2 Секрет в конфиге модуля без `sensitiveKeys` → выход 3, слепка нет (S2).
- AC3 Импорт не трогает отслеживаемый git-ом отличающийся файл (S3).

## Rollback plan
Импорт создаёт `.bak` для заменённых неотслеживаемых файлов и печатает список созданных — откат = удалить созданные, вернуть `.bak`. Экспорт ничего в проекте не меняет.

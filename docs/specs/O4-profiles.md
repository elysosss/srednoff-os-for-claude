# O4: Профили — наборы настроек и хуков под контексты (работа, личное, эксперименты)

> Статус: DRAFT
> Тип: спека-набросок
> Модуль E1: `os-profiles` (опциональный, по умолчанию выключен)
> Зависит от: E1 (флаги модулей), O1 (предполёт endpoint)   Блокирует: O5, O6

## Goal
Запускать Claude Code в проекте с заранее описанным набором: какие модули OS включены, какие хуки и разрешения добавлены, какие исполнители разрешены — одной командой `os-claude -Profile work`, без правки файлов проекта и без записи в `~/.claude`.

## User value
Сейчас переключение «строго на работе / свободно в экспериментах» — это ручное копирование `settings.example.json` и правка флагов. Закрыто, когда профиль выбирается при запуске, активный профиль виден в начале сессии, а выключение профиля возвращает поведение байт-в-байт.

## Non-goals
- Не глобальные профили в `~/.claude/profiles/` (так делает OmniRoute) — запрещено HANDOFF §2.
- Не маршрутизация моделей: профиль **не может** задать `ANTHROPIC_BASE_URL`, ключи API, `apiKeyHelper` (жёсткое ограничение 1).
- Не переключение профиля внутри идущей сессии (оверлей читается при старте).

## Current state
Есть только проектные `settings.json` из примеров. Флаги модулей — в `installed.json` (E1). Launcher-а нет.

## Assumptions
- `ASSUMPTION:` хуки из оверлея `--settings` **складываются** с хуками user/project/local, а не заменяют их. Проверить спайком: два логирующих хука в project и в оверлее.
- `ASSUMPTION:` с `CLAUDE_CONFIG_DIR` Claude Code не читает ничего из `~/.claude` и `~/.claude.json` (глобальный конфиг тоже переезжает). Проверить: пустой каталог + `claude auth status` + поиск обращений Process Monitor-ом.
- `ASSUMPTION:` для одного и того же аккаунта в новом `CLAUDE_CONFIG_DIR` нужен повторный `/login` (доки: `.credentials.json` лежит под этим каталогом). Проверить в фальшивом каталоге.

## Official docs checked
PF-16, PF-17, PF-18. Доки `settings`: `--settings <file-or-json>` действует на одну сессию, выше user/project/local и ниже managed, может задавать любой ключ user-файла (включая `env` — поэтому O1 сканирует оверлеи). `env-vars`: `CLAUDE_CONFIG_DIR` игнорируется в project/local settings, задаётся только из шелла/user/managed. `authentication`: учётные данные — `<CLAUDE_CONFIG_DIR>/.credentials.json`. Проверено в `--help` 2.1.177: `--settings`, `--setting-sources`.

## Architecture (дизайн)
Сравнение механизмов:
| Механизм | Учётка/история/память | Где живёт | Цена |
|---|---|---|---|
| `CLAUDE_CONFIG_DIR` | **раздельные**, повторный вход | отдельный «дом» Claude | глобальное состояние, двойная авторизация, плагины и память не общие |
| `--settings` оверлей | общие | файл, путь передаётся при запуске | не может убрать хук нижнего уровня (только `disableAllHooks`) |
| проектные settings | общие | проект | уже есть; контекст = каталог, а не выбор |

**Решение**: профиль = оверлей `--settings` + карта флагов модулей. `CLAUDE_CONFIG_DIR` — только тип `isolated` для **другого аккаунта** (работа в Team-организации vs личный Pro), выключен до решения владельца; его каталог — путь, заданный владельцем явно, никогда не внутри `~/.claude`.
1. **Определения**: примеры `work`, `personal`, `experiments` в форке `<osRoot>/modules/os-profiles/config/profiles/*.json`; проектные переопределения — `.claude/os-modules/os-profiles/profiles/*.json` (проект выигрывает).
2. **Лаунчер** `os-claude.{ps1,sh} -Profile <name> [-- claude args]`: валидирует профиль по схеме; запрещённые ключи (`env.ANTHROPIC_BASE_URL`, `env.ANTHROPIC_API_KEY`, `env.ANTHROPIC_AUTH_TOKEN`, `apiKeyHelper`, `env.CLAUDE_CODE_USE_*`) → отказ; прогоняет O1 `claude-endpoint`/`claude-credential-override` в быстром режиме; собирает оверлей в `.claude/os-modules/.state/os-profiles/<name>.settings.json`; ставит `SREDNOFF_OS_PROFILE=<name>`; запускает `claude --settings <overlay> ...`.
3. **Флаги модулей**: хуки модулей E1 сначала читают `SREDNOFF_OS_PROFILE` и карту `modules` профиля, затем `installed.json`. Профиль может только **выключить** модуль или включить уже установленный — ставить модули он не может.
4. **Видимость**: SessionStart-хук модуля пишет в `additionalContext` строку «Профиль: work» и тот же факт в маркер для O1.
5. Профиль `experiments` может разрешить исполнителей (внешние модели отдельными процессами, ограничение 2); `work` по умолчанию их запрещает.

## API contracts (интерфейсы и форматы)
```json
{ "schema": 1, "name": "work", "type": "overlay",
  "modules": { "f1": true, "os-probes": false },
  "executors": { "allow": [] },
  "settings": { "permissions": { "deny": ["Read(./.env)"] }, "hooks": { } } }
```
`type: "isolated"` добавляет `"configDir": "<абсолютный путь>"`. Коды выхода лаунчера: 0 — `claude` завершился штатно (код пробрасывается); 10 профиль не найден/невалиден; 11 запрещённый ключ; 12 предполёт O1 = FAIL. `os-claude -List` печатает профили и источник каждого.

## Data model / migrations
Определения — JSON со `schema`; оверлей — производный файл, пересобирается при каждом запуске (не редактируется руками). Миграция `schema` 1→2 — функцией в лаунчере, исходник не переписывается без `-Migrate`.

## Security model
Защищаем от: профиля, который тихо направляет трафик на шлюз или подменяет подписку (валидация + O1); профиля, включающего непроверенный модуль. Не защищаем от: managed-политики (она выше оверлея — это правильно); от `isolated`-каталога, в котором владелец сам выполнил `/login` чужим аккаунтом.

## Risks
| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Оверлей не может снять проектный хук | высокая | среднее | выключение через флаги модулей, а не через settings |
| `isolated` путает историю/память между аккаунтами | средняя | среднее | по умолчанию выключен; O6 не экспортирует `configDir` |
| Лаунчер забыли — сессия без профиля | высокая | низкое | без профиля поведение = текущему; баннер «профиль не выбран» |

## Acceptance criteria
- AC1 Профиль с `env.ANTHROPIC_BASE_URL` не запускается (S1).
- AC2 `-Profile work` выключает модуль `os-probes` без правки `installed.json` (S2).
- AC3 Запуск без лаунчера и с выключенным модулем даёт те же settings, что до O4 (S3).

## Rollback plan
Выключить модуль (E1) → лаунчер отказывается, хуки игнорируют переменную. Удалить: каталог модуля и `.state/os-profiles/`. `isolated`-каталоги лаунчер не удаляет никогда — только печатает их список.

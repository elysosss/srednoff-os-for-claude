# C1: Гигиена префикса — не ломать кэш промптов без нужды

> Статус: DRAFT
> Тип: спека-набросок
> Модуль E1: не модуль — правка правила `80-model-routing.md`, правка `gen-profile-lock.{ps1,sh}`, скрипт ядра `scripts/prefix-report.{ps1,sh}` (вызывается из doctor, O1)
> Зависит от: O1 (точка вызова отчёта)   Блокирует: C2 и C3 (задают им ограничение «не переписывать историю и префикс»)

## Goal
Всё, что OS сама кладёт в начало контекста, меняется только когда это действительно нужно и побайтно стабильно, а агент не переключает модель посреди основной сессии там, где хватает сабагента. Отклонения видны в отчёте, а не угадываются.

## User value
Кэш промптов уже работает хорошо, и спека это признаёт. Замер по локальным транскриптам (17 основных сессий, 1966 ответов, desktop 2.1.156–2.1.281; только числа, без содержимого): `cache_read` = **98,4 %** входных токенов основной сессии. Но **19 промахов** (ход ≥ 20k токенов, из них > 50 % записаны в кэш заново) дали **≈ 3,46 M из 7,26 M** токенов записи в кэш — почти половину. Причины по эвристике: 8 — пауза > 1 ч (TTL, не лечится гигиеной), 1 — пауза 5–60 мин, 2 — смена модели, **8 — пауза < 3 мин без видимой причины (≈ 1,19 M токенов)**. Боль закрыта, когда (а) OS сама не порождает промахов, (б) каждый промах в отчёте имеет названную причину, (в) доля «необъяснённых» падает хотя бы вдвое на следующих 2 неделях работы.

## Non-goals
- Не сжимаем контекст (это C2) и не сокращаем текст правил (апстрим PR #7 уже сделал).
- Не трогаем TTL и платные настройки кэша (`promptCacheTtl` требует v2.1.242+, PF-01).
- Не пытаемся сохранить кэш между сессиями: доки прямо говорят, что последовательные сессии делят префикс только при совпадающем снимке git status — владелец коммитит часто, выигрыш здесь мал.
- Не вводим новый файл правил: каждый файл `.claude/rules/*` стоит токенов в каждой сессии и сабагенте.

## Current state
Слои запроса по докам `prompt-caching`: системный промпт (инструкции, определения инструментов) → контекст проекта (CLAUDE.md, авто-память, правила без `paths:`) → разговор. Изменение слоя инвалидирует всё после него. Что в ЭТОЙ OS трогает каждый слой:

| Слой | Кто меняет | Когда бьёт по кэшу |
|---|---|---|
| Системный промпт | подключение MCP без tool search; включение плагина с MCP; deny-правило на инструмент целиком (`"WebFetch"`, `"Bash(*)"`) — settings подхватываются на лету (PF-16) | сразу, следующий запрос — полное перечитывание |
| Модель/effort | правило 80: «Можно **поднять** модель на критичном шаге... и опустить обратно» → два `/model` = два полных промаха; скилл с `model:` во frontmatter = промах на ход (в `skills-library` и 5 базовых скиллах сейчас **0** таких — проверено grep) | сразу |
| Контекст проекта | `gen-profile-lock` переписывает блок `SREDNOFF-OS:SELECTION` **во 2-й строке** CLAUDE.md, ps1-версия пишет его с CRLF, sh — с LF (одинаковый смысл, разные байты); `session-start-hook` в режиме AUTO-APPLIED пишет CLAUDE.md и правила в момент старта сессии; правки правил; авто-память `MEMORY.md` | правка посреди сессии не применяется и кэш не ломает (доки); ломает префикс следующей сессии и сессии после `/compact` |
| Разговор | `UserPromptSubmit`-хук воркспейса `delegation-reminder.json` — **1035 байт на каждый промпт** (в одной сессии найдено 15 копий `hook_additional_context`); баннер SessionStart ≈ 600 байт один раз | не инвалидирует, но растит разговор линейно: каждая копия перечитывается каждым следующим ходом |

В транскриптах 2.1.260+ список скиллов (`skill_listing`), `date`, `environment` и вывод хуков приходят вложениями в разговор — установка скилла посреди сессии дописывает, а не ломает (совпадает с доками про плагины).

## Assumptions
- `ASSUMPTION:` (кандидат в PLATFORM-FACTS) порядок внутри слоя «контекст проекта» — CLAUDE.md раньше правил и авто-памяти, поэтому правка во 2-й строке CLAUDE.md инвалидирует ~37 КБ после неё. Проверить: две сессии подряд без коммитов, между ними сменить только SELECTION; сравнить `cache_read_input_tokens` первого хода с парой сессий без изменений.
- `ASSUMPTION:` правка CLAUDE.md хуком SessionStart (AUTO-APPLIED) не попадает в уже стартующую сессию. Проверить: пустой проект, сессия, спросить модель о содержимом правила 00.
- `ASSUMPTION:` 8 «необъяснённых» промахов — это `/reload-plugins`, подключение MCP в desktop, fast mode или серверная сторона; ни одну причину нельзя назвать по транскрипту 2.1.177-формата. Проверить: в desktop 2.1.260+ `/usage` показывает `likely cause` последнего промаха (доки `costs`); сопоставить с отчётом.
- Факт, найденный по ходу (кандидат в PLATFORM-FACTS, проверено по полю `version` транскриптов): основная работа идёт в **desktop-приложении с его собственной версией Claude Code (сейчас 2.1.281)**, а не в CLI 2.1.177 из PF-01. Для C1 это значит: `prompt_cache` в statusline (v2.1.251+) и `likely cause` (v2.1.260+) доступны в desktop, но не в CLI — отчёт не должен на них опираться.

## Architecture (дизайн)
Три части, каждая отключаема отдельно:
1. **Правило (для агента).** Не новый файл: заменить в `80-model-routing.md` строку «поднять... и опустить обратно» тремя пунктами (≈ 450 байт, чистый прирост ≈ 300 байт):
   > - Модель и effort выбирай в начале сессии. Поднять мощность на одном шаге — сабагентом с `model`: у него свой кэш, кэш основной сессии не трогается. `/model` посреди задачи перечитывает весь разговор без кэша.
   > - Правка `CLAUDE.md`, правил, `PROFILE.lock`, MCP- и deny-настроек не применится до `/clear`/`/compact` и перестроит префикс — копи такие правки до границы задачи.
   > - `/compact` предлагай на границе задач и перед перерывом больше часа, не посреди работы.
2. **Генератор без шума.** `gen-profile-lock.{ps1,sh}`: блок SELECTION — в конец CLAUDE.md, только LF, запись файла только если байты изменились; список `top:` сортируется детерминированно. Один и тот же вход → одинаковые байты на Windows и Linux.
3. **Отчёт `prefix-report`.** Только чтение. (а) Статика: отпечаток sha256 каждого файла слоя «контекст проекта» + размер; сравнение с прошлым отпечатком из `.claude/os-modules/.state/prefix.json` (gitignored) — «изменилось с прошлого раза: …»; линт: скиллы с `model:`, deny-правила на инструмент целиком, `opusplan`, хуки `UserPromptSubmit`, чей вывод > 300 байт без условия. (б) Динамика: по транскриптам проекта — hit ratio, промахи с классификацией `model_switch / ttl / compact / unexplained`, только числа.

Отвергнуто: отдельный хук-страж, блокирующий `/model` (модель вправе переключать владелец; `ASSUMPTION:` хука PreModelSwitch из доков `prompt-caching` в CLI 2.1.177 нет — проверить строкой в бинаре, как для PF-14); постоянная метрика в statusline (поле `prompt_cache` недоступно в CLI 2.1.177); «замораживать» CLAUDE.md (обновления OS должны доходить).

## API contracts (интерфейсы и форматы)
`prefix-report.ps1 [-ProjectPath .] [-Json] [-Since 14d]` / `prefix-report.sh [--json] [--since 14d] [path]`. Коды выхода: 0 — нарушений нет, 1 — есть предупреждения линта, 2 — ошибка чтения. JSON: `{fingerprint:{file:sha256}, changed:[file], lint:[{rule,file,detail}], cache:{turns, hitRatio, misses:{model_switch,ttl,compact,unexplained}, missTokens}}`. Никакого текста из транскриптов в выводе.

## Data model / migrations
`.claude/os-modules/.state/prefix.json` — последний отпечаток, локальный, в `.gitignore`. Миграция CLAUDE.md: при первом запуске нового `gen-profile-lock` старый блок из 2-й строки удаляется и пишется в конец — одноразовый промах префикса, объявить в CHANGELOG.

## Security model
Отчёт читает `~/.claude/projects/<проект>/*.jsonl`, где лежат сырые выводы инструментов (A-02). Защищаем от утечки через отчёт: выводятся только счётчики и хеши, путь транскрипта не печатается. От чего не защищаем: сам факт чтения транскриптов локальным скриптом.

## Risks
| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Правило о сабагенте вместо `/model` снижает качество: сабагент не видит контекст основной сессии | средняя | среднее | формулировка «на одном шаге»; если шаг требует всей истории — `/model` допустим, Принцип №1 выше экономии |
| Эвристика промахов ошибается (порог 20k/50 %) | высокая | низкое | отчёт — информационный, код выхода не зависит от динамики |
| Перенос SELECTION в конец снижает заметность выбора | низкая | низкое | чтение lock принуждается хуком, не текстом (правило 70) |

## Acceptance criteria
- AC1: повторный запуск `gen-profile-lock` ps1 и sh на одном проекте даёт побайтно одинаковый CLAUDE.md — S1.
- AC2: `prefix-report` называет изменённый файл слоя проекта — S2.
- AC3: линт ловит скилл с `model:` и deny на инструмент целиком — S3.
- AC4: отчёт по транскриптам классифицирует смену модели как `model_switch` и не печатает содержимое — S4.

# D9: Метрики эрозии и аудитор

> Статус: DRAFT
> Тип: спека-набросок
> Модуль E1: `erosion-audit` (режимы `off | on`, по умолчанию `off`); без хуков, кроме опционального напоминания
> Зависит от: E1, C2 (парсер транскриптов M0 — выносится в общую библиотеку ядра), D1 (`docs/specs/maintenance.md` — спек техдолга; `invariants run`), D2 (перемещения карточек в `tasks/`, `attempts`, `returns`, `kind`, `task show --json`), D3 (привязка `session_id → card`, шаг 6), D4 (роль `auditor`, команда `/task-audit`), D6 (снимки рёбер), D8 (отключённые гейты)   Блокирует: правило «каждая N-я карточка — техдолг» в валидаторе D2

## Goal
Раз в 1–2 недели одной командой получить read-only отчёт человеку по четырём метрикам §4 брифа — контекст на закрытую карточку, hotspots, доля возвращённых карточек, новые рёбра графа — с трендом к прошлым отчётам; и механически держать квоту «каждая N-я карточка — техдолг».

## User value
Бриф §4 и §8: человек решает, когда останавливать фичи ради рефакторинга, но сейчас решать не по чему. Закрыто, когда отчёт строится без ручного сбора, числа воспроизводимы из транскриптов и git, а валидатор D2 не пускает в работу (N+1)-ю подряд карточку без техдолга.

## Non-goals
- Аудитор ничего не меняет в проекте: не создаёт карточки, не правит код, не коммитит отчёт. Карточки техдолга по отчёту создаёт планировщик (D4) после решения человека.
- Не дублирует C2: разбор транскриптов — общая библиотека, D9 только группирует его вывод по карточкам.
- Не CI-джоба: главная метрика живёт в локальных транскриптах владельца (`~/.claude/projects/**`), в CI их нет.
- Не оценивает качество кода статическими метриками сложности — это отдельные инструменты проекта.

## Current state
C2 (M0) уже снял по транскриптам доли вывода по инструментам (скрипт `squeeze-measure`, только счётчики); C1 читает те же транскрипты для отчёта о промахах кэша. Третий потребитель — D9, поэтому парсер переезжает из модуля `squeeze` в ядро (`scripts/lib/transcript-stats`), модуль C2 им пользуется. Наблюдается в транскриптах десктопа 2.1.281: у записей есть поля `sessionId`, `cwd`, `gitBranch`, `timestamp`, у ответов — `message.usage`; сабагенты лежат в `<session>/subagents/`.

## Architecture (дизайн)
Команда `erosion-audit.{ps1,sh} [-Since 14d] [-Json] [-Project P]` → сбор → метрики → отчёт.
1. **Контекст на закрытую карточку.** Карточки, перешедшие в `done` за период (D2) → их сессии (привязка D3 или эвристика) → транскрипты с совпадающим `cwd` → по общей библиотеке: `peak_ctx` (максимум за ход `input + cache_read + cache_creation`), `total_in`, число ходов, число сабагентов и **`reads_outside`** — доля различных прочитанных файлов вне `context_files ∪ touch_allowed ∪ spec` карточки. Последняя — прямой механический замер правила §2 «агенту достаточно спека, контракта и затронутых файлов». Медиана и p90 за период, дельта к медиане трёх прошлых отчётов.
2. **Hotspots.** `git log --since --no-merges --numstat` → изменения по файлу и по модулю D6; ранг = число изменяющих коммитов × текущий размер в строках; исключения — `exclude` (lock-файлы, сгенерированное); плюс «файлы, которые меняли ≥ 3 разные карточки»: коммит приписывается карточке, файл которой тот же коммит (или тот же squash-мерж PR) переносит в `tasks/done/`.
3. **Возвраты.** Из D2: доля карточек с непустым `returns` или прошедших через `returned/` (по `git log` перемещений) среди закрытых и возвращённых за период; распределение `attempts`; карточки, ушедшие в `task split`, — отдельным списком (по полю `replaces:` новых).
4. **Новые рёбра.** Снимки D6 на начало и конец периода; нет снимка начала — D6 запускается на дереве старого коммита, распакованном `git archive` во временный каталог **вне** репо (не `git worktree`: тот пишет в `.git/worktrees`).
5. **Сопутствующее:** гейты в `disabled` (D8) и просроченные, high-risk PR за период (D7/D8, через `gh` только чтение, если доступен), новые неизвестные термины (D10), красные инварианты `invariants run` D1.
6. **Отчёт:** `.claude/os-modules/.state/erosion-audit/<date>.{json,md}` (gitignored); красные флаги по порогам; «кандидаты в техдолг» — top hotspots и модули с растущим `peak_ctx`, каждому id вида `2026-10-01#H3`. Опубликовать отчёт в репо (`docs/reports/erosion/`) может только человек флагом `-Publish` — это действие человека, не аудитора.
7. **Роль «Аудитор»** принадлежит D4 (`auditor`: Read, Grep, Glob, Bash, PowerShell; без Edit/Write) и вызывается `/task-audit`: запускает `erosion-audit`, читает готовый JSON и пишет человеку разбор. «Не меняет что-либо» механически держат отсутствие Edit/Write и путевые права роли в D3 (разрешён только каталог отчётов); shell-слой D3 — по возможности, поэтому итоговую гарантию даёт D8 (изменения вне карточки не мержатся). Расхождение путей: D4 пишет `.state/roles/audit/`, здесь — `.state/erosion-audit/`; при сведении спек берётся путь модуля, который пишет файл (правило E1 о `.state/<id>/`).
8. **Квота техдолга** `debt-quota-check` — без новых полей D2: карточка техдолга = `kind: refactor` со `spec` на раздел `docs/specs/maintenance.md` (D1), существование якоря проверяет линтер D1 L1; раздел пишет планировщик по пункту отчёта. При `task start` валидатор D2 зовёт проверку: если среди последних `debt_every − 1` стартовавших карточек (по `git log` переносов в `active/`) нет техдолга, стартовать можно только техдолг. На сервере та же проверка — в integrity D8 по переносам в `tasks/done/` ветки по умолчанию.
9. **Напоминание** (опционально, `remind: off`): SessionStart-хук модуля печатает одной строкой, что отчёт просрочен на N дней (см. допущение про `systemMessage`).
Отвергнуто: LLM-аудитор, считающий метрики сам (невоспроизводимо); запуск в CI (нет транскриптов).

## API contracts (интерфейсы и форматы)
Конфиг `.claude/os-modules/erosion-audit/config/default.json`: `{"interval_days": 14, "debt_every": 5, "exclude": ["**/*.lock", "**/package-lock.json", "**/Cargo.lock"], "thresholds": {"peak_ctx_growth": 0.2, "reads_outside": 0.3, "returned_share": 0.25}, "remind": "off"}`. Отчёт JSON: `{schema, period:{from,to}, cards:[{id, sessions, peak_ctx, total_in, reads_outside, mapping:"exact|heuristic"}], hotspots:[{path, module, commits, loc, rank}], returned:{share, attempts_hist}, new_edges:[...], gates_disabled:[...], flags:[...], debt_candidates:[{id, kind, target}], unparsed_records: n}`. Коды: `0` отчёт построен; `2` конфиг; `4` нет данных (ни одной закрытой карточки) — отчёт всё равно пишется с пустыми секциями.

## Data model / migrations
История отчётов — локально, по одному файлу на прогон; тренд считается по последним трём. `schema` целое; старые отчёты не переписываются.

## Security model
Транскрипты могут содержать секреты (A-02): D9 читает только числа `usage`, имена инструментов и пути из входа Read/Grep/Glob; в отчёт не попадает ни одной строки содержимого; пути — только внутри проекта (`cwd` совпадает). Отчёт не уходит в сеть. Не защищаем: чувствительные имена файлов в путях (отчёт gitignored, публикация — решение человека).

## Risks
| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Связь «сессия → карточка» неточна | средняя | высокое | поле `mapping` в отчёте; требование к D3 отдавать привязку `--json` |
| Формат транскриптов меняется при самообновлении | средняя | среднее | `unparsed_records`, пробы O3 |
| Метрика контекста растёт из-за модели, а не архитектуры | средняя | среднее | в отчёте модель и версия на карточку; сравнение внутри одной модели |
| Квота обходится `refactor`-карточкой «ни о чём» | средняя | низкое | `spec` обязан вести в `maintenance.md`, раздел ссылается на пункт отчёта; ревью человека |

## Acceptance criteria
1. На фикстурах транскриптов и карточек `peak_ctx` и `reads_outside` совпадают с эталоном — S1, S2.
2. Hotspots исключают lock-файлы — S3.
3. Снимок старого коммита строится без изменений в `.git` и рабочем дереве — S4.
4. Квота техдолга срабатывает на (N)-й карточке — S5.

## Rollback plan
`os-module mode erosion-audit off` — команда отказывает, хук-напоминание молчит, валидатор D2 пропускает квоту. `uninstall --purge` удаляет историю отчётов. Опубликованные человеком отчёты остаются в репо как документы.

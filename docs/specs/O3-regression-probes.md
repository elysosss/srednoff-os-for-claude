# O3: Регрессионные пробы — что тихо сломается после запуска

> Статус: DRAFT
> Тип: спека-набросок
> Модуль E1: `os-probes` (опциональный модуль, по умолчанию выключен)
> Зависит от: O1 (предполётные проверки), E1   Блокирует: —

## Goal
После обновления Claude Code (или смены машины/шелла) одной командой узнать, какие опоры OS на платформу перестали держать: хук не вызывается, его ответ молча игнорируется, новый инструмент идёт мимо матчеров, хук упирается в таймаут и пропускает вызов.

## User value
Doctor отвечает «запустится ли» — он кормит скрипт хука JSON-ом напрямую, минуя Claude Code. Пробы отвечают «что тихо сломается»: они проверяют **связку** Claude Code ↔ хук. Все известные поломки OS были тихими: `grep -P` без `--` на паттерне `-----BEGIN` (правило private_key не срабатывало в bash-порте), локаль, отвергнутая `grep -P`, отсутствие `jq` (`hook-lib.sh`), `MultiEdit`/`NotebookEdit` вне матчеров (PR #10). Платформенные — того же класса: невалидный `updatedToolOutput` молча игнорируется (PF-02), таймаут `PreToolUse` пропускает вызов (PF-12), `http`-хук fail-open (PF-13). Закрыто, когда каждая такая опора имеет пробу с вердиктом HOLDS/BROKEN и ссылкой на строку PLATFORM-FACTS.

## Non-goals
- Не заменяет doctor, eval-сьют и CI; не гоняется в CI (нужен вход в подписку).
- Не запускается автоматически: живые пробы тратят квоту подписки.
- Не тестирует качество ответов модели — только механику хуков.

## Current state
`doctor` hook-canary и CI-джоба `hook-canary` — скрипт-уровень. PLATFORM-FACTS сверен вручную по бинарю 2.1.177. Реальный пробел, который проба поймала бы уже сейчас: `settings.windows.example.json` вешает `block-dangerous-bash` на матчер `Bash`, а в 2.1.177 на Windows есть инструмент `PowerShell`, включённый по умолчанию (PF-28) — его вызовы идут мимо хука.

## Assumptions
- `ASSUMPTION:` `claude -p` под OAuth-подпиской запускает проектные хуки так же, как интерактивная сессия. Проверить: проба P-00 (ниже) — она и есть проверка.
- `ASSUMPTION:` полный прогон живых проб ≈ 10–20 тыс. токенов квоты. Проверить `/usage` до и после первого прогона.

## Architecture (дизайн)
Три слоя, от дешёвого к дорогому, строго последовательно (ограничение 4):
1. **Статический (бесплатно, всегда)**: версия Claude Code vs последняя пропробированная (`last.json`); отпечатки контрактных строк в бинаре; валидность каждого settings-файла, где подключены хуки OS. Результат — HOLDS/CHANGED, не BROKEN.
2. **Окружение хука (бесплатно)**: SessionStart-хук модуля (если включён) пишет, **как Claude Code реально запускает хуки**: какой `bash` в PATH (на Windows `System32\bash.exe` — это WSL, не Git Bash), `LANG/LC_ALL`, находится ли `jq`, проходит ли `srednoff_pcre_ok`, версия PowerShell. Doctor проверяет это в своём шелле; проба — в шелле Claude.
3. **Живые пробы (квота, по команде)**: временный проект в scratch, `claude -p` с `--settings <probe-overlay.json>` (оверлей добавляет логирующие хуки с матчером `*`) и детерминированным промптом «выполни ровно этот вызов». Вердикт — по логу хуков, а не по тексту модели. Каталог проб:
   - P-00 хуки вообще вызываются в `-p`; P-01 инвентаризация имён инструментов vs матчеры OS (новое имя, пишущее файлы или исполняющее команды, вне матчеров → BROKEN; ловит случай `PowerShell`);
   - P-02 deny от `block-dangerous-bash` реально останавливает вызов (канарейка `mkfs` на несуществующее устройство, вызов блокируется до исполнения);
   - P-03 `updatedToolOutput` для Read применяется (PF-02) — важно для F1; P-04 `updatedInput` без `permissionDecision` (PF-05);
   - P-05 латентность каждого хука OS в реальном запуске vs таймаут события (PF-12; `UserPromptSubmit` 30 с) — p95 > 50 % бюджета → WARN;
   - P-06 форма `tool_response` совпадает с PF-19 (закрывает A-05).
Каждая проба объявляет `factId` — при BROKEN отчёт говорит, какую строку PLATFORM-FACTS перепроверить.

**Предполёт**: перед слоем 3 обязательны O1 `claude-endpoint` и `claude-credential-override` = OK. Если стоит `ANTHROPIC_API_KEY`, `-p` списал бы деньги с ключа (PF-18) — проба отказывается.
**Напоминание**: SessionStart-хук при смене версии Claude Code добавляет `additionalContext` «Claude Code обновлён X→Y, запустите /os-probe». Сам ничего не запускает.

## API contracts (интерфейсы и форматы)
`bin/os-probe.{ps1,sh} [--static] [--env] [--live] [--only P-0x] [--yes]`; `/os-probe` — тонкая обёртка, `--live` только после подтверждения. Выход: 0 всё HOLDS; 1 есть BROKEN; 2 предполёт не пройден. Отчёт `{claudeVersion, probedAt, probes[{id, layer, factId, verdict: HOLDS|BROKEN|CHANGED|INCONCLUSIVE, evidence}]}`. `evidence` — только имена полей/инструментов и тайминги, без содержимого файлов.

## Data model / migrations
`.claude/os-modules/.state/os-probes/last.json` (версия, вердикты), `runs/<UTC>.json` (последние 20). Временный проект создаётся в системном temp и удаляется после прогона; транскрипт сессии пробы остаётся в `~/.claude/projects/<slug-temp>` — его путь печатается, удаление по флагу `--purge-transcript`.

## Security model
Пробы используют только канарейки (фиктивные ключи формата `sk-ant-api03-` + фиксированный мусор, несуществующие устройства), работают в пустом временном проекте, без сети кроме самого Claude. Не защищаем от: ложного HOLDS, если платформа меняет поведение только в интерактивном режиме.

## Risks
| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Модель не делает запрошенный вызов | средняя | низкое | INCONCLUSIVE + один повтор; не BROKEN |
| Опасная канарейка исполнится при сломанном deny | низкая | высокое | канарейка безвредна даже при исполнении (`mkfs` на `/dev/null-probe`), пустой temp-проект |
| Пробы тратят квоту незаметно | низкая | среднее | только `--live` + подтверждение, оценка в токенах перед стартом |

## Acceptance criteria
- AC1 Вызов инструмента, не покрытого матчерами OS, даёт P-01 BROKEN с именем инструмента (S1).
- AC2 Невалидный `updatedToolOutput` определяется как BROKEN, а не «OK, хук отработал» (S2).
- AC3 При выставленном `ANTHROPIC_API_KEY` живые пробы не стартуют (S3).

## Testing plan
```gherkin
Scenario: S1 новый инструмент мимо матчеров
  Given хуки OS с матчером "Bash" и лог пробы с вызовом инструмента "PowerShell"
  When оцениваю пробу P-01
  Then вердикт "BROKEN" и evidence содержит "PowerShell"
Scenario: S2 замена вывода молча отброшена
  Given лог: хук вернул updatedToolOutput, а модель получила оригинал-канарейку
  When оцениваю пробу P-03
  Then вердикт "BROKEN" и factId "PF-02"
Scenario: S3 предполёт блокирует живые пробы
  Given в окружении выставлен ANTHROPIC_API_KEY
  When запускаю os-probe с "--live --yes"
  Then код выхода 2 и claude не запускался
```
Оценщики проб тестируются на записанных логах (без модели); живой прогон — ручной, на каждой новой версии Claude Code.

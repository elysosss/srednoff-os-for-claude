# C3: Двухуровневая память — журнал на всё, в контекст только проверенное

> Статус: DRAFT
> Тип: спека-набросок
> Модуль E1: `memory`
> Зависит от: E1 (формат модуля), журнал наблюдений (влит апстримом в #18, 2026-09-15), C1 (не трогать префикс)   Блокирует: —

## Goal
Всё, что стоит помнить о проекте, дописывается в append-only журнал (уровень 1, в контекст не грузится). В контекст сессии попадает только короткий дайджест (уровень 2) из записей, которые **владелец** продвинул и чьё доказательство механически проверяется. Заметки и карта проекта связаны с журналом ссылками, а не копиями.

## User value
Сейчас есть два полюса: журнал `.agent/log/` (0 токенов, но агент его не видит, пока не откроет) и авто-память Claude Code (видна всегда, но пишет её сама модель без проверки, лежит вне git, на одной машине). Боль: решение, принятое месяц назад, либо забыто, либо «вспомнено» неверно — в том числе после инъекции из прочитанной веб-страницы. Закрыто, когда (а) новая сессия видит продвинутые решения без единого Read, (б) ни одна строка не попадает в дайджест без команды владельца, (в) устаревшая запись сама выпадает из дайджеста.

## Non-goals
- Не векторный поиск, не граф, не база данных, не внешний сервис (claude-mem уже отвергнут в журнале osint-os: хостинг, добавляет контекст).
- Не замена авто-памяти Claude Code: она остаётся для личных предпочтений (см. Architecture).
- Не автоматическое продвижение моделью или эвристикой — только владелец.
- Не нав-карта как память: то, что выводится из кода (структура, пути), в память не пишется — так же решили доки авто-памяти и dsh (отказ от центрального индекса заметок).

## Architecture (дизайн)
| Артефакт | Уровень | Кто пишет | В контексте | В git |
|---|---|---|---|---|
| `.agent/log/YYYY-MM.md` — журнал | 1 | модель и владелец, только дописывание | нет | да |
| `.agent/notes/{proposed,implemented,rejected}/YYYY-MM-DD-тема.md` — заметки | 1 | модель и владелец | нет | да |
| `.agent/NAV.md` — карта «где что лежит» | справка | владелец | нет | да |
| `.agent/memory/promotions.log` — события продвижения | шлюз | **только** `bin/memory-promote` из команды владельца | нет | да |
| `.agent/memory/DIGEST.md` — дайджест | 2 | генератор, детерминированно | да, через SessionStart | да |
| `MEMORY.md` авто-памяти | вне модуля | Claude Code | да | нет |

Поток: запись в журнал → владелец `/os-memory promote 2026-09-27#2 --evidence commit:abc1234` → скрипт проверяет доказательство, дописывает событие с sha256 текста записи → генератор пересобирает `DIGEST.md` → хук SessionStart (`startup|resume|clear|compact`) отдаёт дайджест как `additionalContext`.
- **Адресация без правки старых строк:** id записи = `дата#порядковый номер за день` в месячном файле. Append-only делает номер стабильным; sha256 текста в событии ловит любую правку задним числом.
- **Проверка:** `commit:<sha>` существует (`git cat-file -e`), `file:<путь>[:строка]` существует, `note:<путь>` существует; `url:` проверить локально нельзя — только с `--force` и пометкой в дайджесте.
- **Устаревание:** на SessionStart дешёвая перепроверка доказательств; не прошедшая запись не рендерится и перечисляется в `/os-memory review`. SessionStart ничего не пишет в отслеживаемые файлы.
- **Замена:** `--supersedes <id>` скрывает старую запись из дайджеста, журнал не трогается.
- **Бюджет:** дайджест ≤ 40 строк и ≤ 4 000 символов; сверх — выпадают самые старые продвинутые, остаются в журнале. Первая строка — указатели: журнал, заметки, NAV.
- **Связь с C1:** дайджест приходит вложением в разговор, а не в CLAUDE.md, поэтому не меняет префикс и не грузится в каждый сабагент; байты стабильны между сессиями (сортировка по id, без метки времени генерации).
- **Разделение с авто-памятью:** авто-память — предпочтения и обратная связь владельца (типы `user`, `feedback`), машинно-локально; дайджест — решения и ограничения проекта, общие и ревьюемые. `memory-check` предупреждает о дублях между ними.

Отвергнуто: дайджест в CLAUDE.md через `@`-импорт (грузится в каждый сабагент, меняет префикс при каждом продвижении); `autoMemoryDirectory` → `.agent/memory` (Claude пишет туда сам, шлюз пришлось бы строить запретом записи, что ломает авто-память); продвижение моделью с последующим одобрением (одобрение по привычке — тот же автопилот).

## API contracts (интерфейсы и форматы)
- Команды: `/os-memory promote <id> --evidence <kind:value> [--supersedes <id>] [--force]`, `/os-memory review`, `/os-memory render`. Исполнение — строкой `` !`...` `` в файле команды (A-10), скрипт `bin/memory.{ps1,sh}`.
- Событие в `promotions.log` (одна строка JSON): `{"ts":"2026-09-27","op":"promote|demote","id":"2026-09-27#2","sha256":"…","evidence":"commit:abc1234","supersedes":null}`.
- Хук PreToolUse(Edit|Write|MultiEdit|Bash) запрещает изменения под `.agent/memory/` с причиной «продвижение — только командой владельца»; для Bash проверка best-effort (PF-21).
- `validate-journal.{ps1,sh}`: 0 — ок; 1 — строка журнала изменена или удалена относительно merge-base, sha256 события не совпал, найден секрет по паттернам `hook-lib`; 2 — ошибка чтения.
- `config/default.json`: `{"enabled": false, "digestMaxChars": 4000, "digestMaxLines": 40, "recheckOnStart": true}`.

## Data model / migrations
Существующие записи osint-os без id продвигаются адресом `дата#номер` — переписывать их не нужно. `DIGEST.md` можно удалить и пересобрать из журнала и событий в любой момент. Смена формата события — поле `v` в JSON, генератор читает все известные версии.

## Security model
Защищаем от: самопродвижения моделью; закрепления prompt-инъекции в постоянном контексте (запись из вредной страницы остаётся в уровне 1 и в контекст не попадает без владельца); тихой правки истории (append-only + sha256); секретов в коммитуемом журнале (скан `validate-journal`). Не защищаем от: владельца, продвинувшего неверную запись; модели с шеллом, целенаправленно обходящей best-effort-проверку Bash (журнал git это покажет, но не предотвратит).

## Risks
| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Владелец не продвигает ничего — дайджест пуст | высокая | среднее | `/os-memory review` показывает кандидатов по типу и возрасту; пустой дайджест — не ошибка |
| Дайджест дублирует авто-память | средняя | низкое | `memory-check`, разделение по типам |
| Порядковые номера ломаются ручной вставкой строки в середину | низкая | среднее | `validate-journal` ловит, sha256 события не совпадает |
| SessionStart-хук не срабатывает (фон, ошибка) | низкая | низкое | fail-open: сессия без дайджеста, журнал доступен через Read |

## Acceptance criteria
- AC1: выключенный модуль ничего не добавляет в контекст — S1.
- AC2: запись попадает в контекст только после продвижения владельцем — S2.
- AC3: модель не может продвинуть запись сама — S3.
- AC4: правка задним числом ловится и выкидывает запись из дайджеста — S4.
- AC5: запись с исчезнувшим доказательством выпадает из дайджеста — S5.

Парность `.ps1`/`.sh` для генератора, хуков и `validate-journal`. Вручную: неделя работы в osint-os — сколько записей продвинуто и был ли дайджест полезен (строка `decision` в журнал).

## Rollback plan
`enabled=false` — хук SessionStart молчит, запрет записи снимается. Удаление модуля не трогает журнал, заметки и NAV: это обычные файлы `.agent/`, которые существовали и до модуля. `promotions.log` и `DIGEST.md` можно удалить без потерь — журнал остаётся полным.

## Estimate (оценка объёма)
Формат id/доказательств + `validate-journal` ps1/sh — 1 сессия. Команда `/os-memory` + скрипт продвижения + запрет записи — 1. Генератор дайджеста + SessionStart + перепроверка — 1. Тесты S1–S5 на обеих платформах, документация — 0,75. Итого **≈ 3,75 сессии**. Взорвать может: A-10 не подтвердится (нет канала «только владелец» — тогда продвижение через скрипт, который владелец запускает сам в терминале); ветка журнала не влита в main.

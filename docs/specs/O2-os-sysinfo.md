# O2: `/os-sysinfo` — снимок окружения для разбора проблем

> Статус: DRAFT
> Тип: спека-набросок
> Модуль E1: не модуль — скрипт ядра `scripts/sysinfo.{ps1,sh}` + команда `/os-sysinfo`
> Зависит от: O1 (переиспользует вердикты doctor)   Блокирует: —

## Goal
Одной командой собрать в файл версии, ОС, установленные CLI, статус Docker, состав OS и вердикт doctor — так, чтобы файл можно было приложить к issue, не вычищая руками секреты и персональные данные.

## User value
Сейчас для разбора бага («у меня 20/46 эвалов») приходится по кускам спрашивать версию grep, локаль, jq, Claude Code. Закрыто, когда один файл отвечает на все эти вопросы и проходит секрет-скан OS без единого совпадения.

## Non-goals
- Не отправляет файл никуда: ни в issue, ни в чат, ни модели. Делиться — решение владельца.
- Не диагностирует (это O1) и не проверяет поведение (это O3); только фиксирует факты.
- Не собирает значения переменных окружения, содержимое settings, логи хуков, транскрипты.

## Current state
`status.*` даёт однострочник, `doctor.* --json` — вердикты. Версий внешних инструментов (grep, jq, bash, PowerShell, Docker) не собирает никто; грабли HANDOFF §6.6 (локаль) диагностировались вручную.

## Assumptions
- `ASSUMPTION:` `docker version --format '{{json .}}'` и выбранные поля `docker info --format` (`ServerVersion, OperatingSystem, OSType, Driver`) не содержат учётных данных. Проверить на машине с настроенными registry-mirror и прокси.

## Questions
Блокирующих нет. Место файла выбрано по умолчанию (см. Architecture), переопределяется `-Out`.

## Architecture (дизайн)
**Принцип — allow-list, а не вычистка.** Скрипт собирает только перечисленные поля; всё, чего нет в списке, не попадает в файл вообще.
1. **Секции**: `platform` (ОС, билд, архитектура, локаль, кодовая страница консоли), `shells` (PowerShell `$PSVersionTable`, bash, Git for Windows), `claude` (версия, `authMethod`, `apiProvider`, `subscriptionType` — без email/org), `tools` (git, gh, jq, grep + `grep -P` работоспособность и выбранная локаль из `srednoff_pcre_locale`, python, node, docker, behave в venv модулей), `docker` (клиент/сервер версии, демон доступен да/нет, имя текущего контекста без endpoint), `os` (версия OS, `osRoot` обезличен, модули `{id, version, enabled}`, какие события хуков подключены — имена скриптов без аргументов), `env-presence` (для фиксированного списка имён: `ANTHROPIC_*`, `CLAUDE_*`, `HTTPS_PROXY`… — **только** `set/unset/empty`), `doctor` (вердикты O1 без `detail`).
2. **Обезличивание**: домашний каталог → `~`, имя пользователя → `<user>`, имя хоста → `<host>`, e-mail и IP (кроме 127.0.0.1) → `<redacted>`. PATH не выводится целиком — только какие из нужных бинарей в нём найдены.
3. **Последняя линия — fail-closed**: готовый текст прогоняется через секрет-скан `hook-lib` (13 правил). Любое совпадение → файл **не пишется**, печатается правило и секция; маскировать и «всё равно сохранить» нельзя.
4. **Куда**: `<project>/.claude/os-modules/.state/sysinfo/sysinfo-<UTC>.md` + `.json`. Перед записью `git check-ignore` на путь; если каталог не игнорируется — отказ с подсказкой добавить `.state/` в `.gitignore` или указать `-Out`. `-Out` внутри `~/.claude` отвергается (HANDOFF §2).
5. Внешние команды — с таймаутом 5 с каждая, последовательно; упавшая команда даёт `unavailable`, а не прерывание.

## API contracts (интерфейсы и форматы)
`scripts/sysinfo.ps1 [-ProjectPath .] [-Out <dir>] [-Json] [-NoDoctor]`, `.sh` — те же флаги в `--kebab`. Выход: 0 записано; 3 секрет-скан сработал (файл не записан); 4 каталог не игнорируется git. JSON: `{schema:1, generatedUtc, platform{}, shells{}, claude{}, tools{name:{version|null, ok}}, docker{}, os{}, envPresence{name:"set|unset|empty"}, doctor[{name,status}]}`. Markdown — тот же JSON, отрендеренный таблицами. `/os-sysinfo` запускает скрипт и печатает только путь и сводку «N инструментов, M проблем».

## Data model / migrations
Файлы-снимки, `schema` в JSON; новая версия схемы добавляет поля, старые не переименовываются. Хранятся последние 10, более старые удаляет сам скрипт (только в своём каталоге, по маске имени).

## Security model
Угрозы: секрет в отчёте (ключ в env, токен в URL прокси, пароль в docker context), персональные данные (имя, e-mail, орг), случайный коммит отчёта. Защита: allow-list + обезличивание + fail-closed скан + проверка gitignore. Не защищаем от владельца, который сам вставит файл куда угодно.

## Risks
| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Новая версия инструмента печатает секрет в `--version` | низкая | высокое | fail-closed скан |
| Скан ложно срабатывает на версию/хеш | средняя | низкое | правило и секция в ошибке; allow-list сужается, а не скан |
| Docker Desktop висит при `docker info` | средняя | низкое | таймаут 5 с |

## Acceptance criteria
- AC1 Значение переменной `ANTHROPIC_API_KEY` никогда не появляется в файле, только `set` (S1).
- AC2 Совпадение секрет-скана → файла нет, выход 3 (S2).
- AC3 Неигнорируемый каталог → отказ, выход 4 (S3).
